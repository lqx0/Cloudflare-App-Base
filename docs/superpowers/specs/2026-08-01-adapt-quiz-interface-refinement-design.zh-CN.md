# aDaptQuiz Quiz 与 Question Bank 界面优化设计

## 状态

已确认设计方向：克制的极简卡片式。本设计只优化展示，不改变产品行为、数据、权限或隐私边界。

## 目标

- 让 Quiz 从介绍、作答到结果的流程更容易阅读。
- 提高新增题目和查看题库的效率，同时避免界面过于密集。
- 保留现有共享 `SiteLayout`、响应式行为、全英文 UI 和黑白灰优先的视觉语言。
- 保留所有当前功能、正式版本提示和无障碍契约。

## 视觉语言

- 以黑、白和中性灰为主。
- 现有 primary 色只用于主要操作、选中答案和少量状态强调。
- 使用克制的边框、适度圆角，尽量不使用阴影。
- 主要依靠间距、字体层级和分隔线，不加入渐变、插图或装饰动画。
- 桌面端保持舒适内容宽度，移动端完整可用。

## Quiz 界面

### 页面结构

- 增加紧凑页面标题区，显示 `Quiz`、简短说明和 `3 questions` 等当前轮次信息。
- 将介绍、作答和结果分别组织为一个清楚的主面板，而不是互不关联的文字块。
- Error、Loading、题库不足和邮件不可用状态靠近所影响的操作显示。

### 开始说明

- 将三题组成、页面内存隐私说明和正式版历史提示整理为简洁概览。
- 使用三个小型题型标签说明本轮组成。
- `Start quiz` 是唯一主要操作。

### 作答

- 题目编号使用 `01`、`02`、`03`，并显示紧凑题型标签。
- 选择题和判断题使用整行可选区域，并清楚显示选中状态。
- 问答输入区域保持足够空间，并与题目明显关联。
- 显示简单的已答题数量提示，`Submit answers` 位于面板末尾。
- 保持三题必答以及提交后锁定答案的现有规则。

### 结果

- 继续显示题目编号和题型标签，帮助用户定位。
- 用两个安静的中性区域区分 `Your answer` 与 `Correct answer` 或 `Reference answer / Evaluation guidance`。
- `Start a new quiz` 为主要操作，`Send a copy` 为次要操作。
- 保持主动确认、配置不可用、失败重试和本轮发送锁定行为。

## Question bank 界面

### 页面结构

- 桌面端使用双栏布局：左侧新增题目，右侧现有题库。
- 小屏幕按相同顺序上下排列。
- 页面标题保持紧凑，并在题库标题附近显示题目数量。

### 题目表单

- 表单放在克制的边框面板内。
- 用三个紧凑、支持键盘操作的题型选择器替换原生下拉框。
- 只显示当前题型需要的字段。
- 为选项录入和参考指导提供简短帮助文字。
- Validation Error 靠近表单显示，`Add question` 是唯一主要操作。
- 新增成功后清理合适字段，同时保留合理的当前题型。

### 题库列表

- 每题使用紧凑的边框行／卡片，显示题型、题目和相关答案摘要。
- 选择题显示选项，但不增加编辑控件。
- 增加明确空状态，说明通过左侧表单新增后题目会显示在此处。
- 保留编辑、删除和可用性控制将在正式版本实现的已批准提示。

## 无障碍与响应式

- 保留语义化 `fieldset`、`legend`、Label、Live Region、Alert 和 Dialog Description。
- 选项行必须支持键盘操作，并继续使用原生 Radio 语义。
- 浅色与深色主题中的文字和边框必须保持清楚对比度。
- 双栏题库在小屏幕折叠，不产生横向滚动。
- 主要操作保持容易触达，不依赖只有 Hover 才能看到的信息。

## 范围边界

本次优化不增加题目编辑、删除、停用、Quiz 历史、评分、计时、AI 评价、后台答卷列表或收件邮箱设置。不改变 Worker API、D1 Schema、邮件发送规则或管理员授权。

## 验证

- 运行全部 aDaptQuiz 聚焦测试和完整测试。
- 运行 ESLint、App/Worker TypeScript 检查、Production Build 和 `git diff --check`。
- 完成前在运行中的本地页面检查桌面和窄屏宽度。
